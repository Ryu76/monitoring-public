# 통합관제 장애복구 절차서

## 원칙

장애 복구 절차는 운영 데이터에 쓰기 전에 영향 범위, backup, rollback, 승인자를 확인한다.

## 기본 흐름

1. health/API/Worker/Scheduler/DB 연결 상태와 로그를 확인한다.
2. 비밀값·token·DB password를 출력하지 않고 오류 시각·요청 ID·서비스 상태만 기록한다.
3. API/Worker/Scheduler는 분리된 재시작 절차를 사용한다.
4. DB migration/partition 오류는 승인된 rollback script와 backup 검증 후 처리한다.
5. Agent spool은 ACK 전 데이터를 삭제하지 않는 구조가 검증된 뒤에만 재전송한다.
6. 복구 후 핵심 API, metric 수집, alert/incident 흐름, 회귀 테스트를 수행한다.

## 상태

실제 운영 장애 대응 절차는 개발 DB·배포 방식 확정 후 구체화한다.
